## 文件范围

- `index.html`：页面结构、启动期设备识别和外部资源加载顺序。
- `styles.css`：页面样式。
- `js/data.js`：网址、分类、排名和照片静态数据。
- `js/app.js`：DOM 渲染与交互逻辑。
- `PROJECT_STATUS.md`、`docs/CONTEXT_INDEX.md`、`docs/IMPLEMENTATION_PLAN.md`、`docs/HANDOFF_CURRENT.md`：长项目状态与交接。

## 关键决定

- 不增加第二份网站数据；`renderCards()` 生成一次 `orderedLinks`，同时驱动卡片和速览。
- 1080px 是速览显示断点；桌面通过第三个网格列预留空间，窄屏直接隐藏。
- 使用原生按钮和现有 `scrollIntoView()` 定位，不增加依赖或新的滚动状态。
- 运行时比较卡片与速览的 `data-*` 顺序，出现偏差立即报错。
- 站内与 Google 搜索共用一个输入框；主提交仍调用现有站内搜索，带 `formaction` 的次级按钮用原生 GET 在新标签页提交 `q` 参数。
- 现有 `google.cn.png` 是 Chrome 图标，因此使用内联四色 G SVG，不新增资源文件或外部图片请求。
- 图标图片默认可见、备用标识默认隐藏；只在原生 `error` 事件时切换备用状态，不增加预加载器或额外状态。
- ToolKnit 与现有节点入口共用 `.promo-banner`；推广区独立横跨顶部，620px 以下及移动设备改为单列，不新增依赖。
- 保留首屏设备识别脚本内联；CSS 置于根目录，数据与交互使用按顺序加载的经典脚本，避免引入打包器和 `file://` 下的 ES Module 限制。
- 两段内嵌头像 Base64 均由 `assets/avatar.jpeg` 立即覆盖，直接删除重复数据并保留同一图片路径。
- 速览与搜索继续共用 `focusHighlightedCard()`；定位函数统一更新 `activeHighlightName` 和卡片类名，避免两套高亮逻辑。
- 回顶监听只在点击目标恰好是 `.site-header` 时触发，子元素链接继续使用原事件，不增加覆盖层。
